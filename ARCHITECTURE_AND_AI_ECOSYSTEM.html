Core Value Proposition

What Critical Industry Problems Did We Solve?

CareerLens AI replaces fragile keyword matching and untrustworthy black-box LLMs with a mathematically grounded, verifiable intelligence pipeline.

Problem 1: ATS Keyword Stuffing

Traditional ATS Parsers

Standard Applicant Tracking Systems rely on literal regex matching. A candidate writing "Flask & FastAPI microservices" receives 0 points if the recruiter searched for "Python Web Frameworks".

  • Trivially defeated by white-text keyword stuffing
  • Zero understanding of semantic synonymy or hierarchy
  • Treats unrelated words in random sections as valid skills

✨ Our Solution

GLiNER zero-shot NER + 117-Entity Canonical Ontology extracts verified context and normalizes tech stacks without regex fragility.

Problem 2: LLM Hallucinations

Pure LLM Evaluators

Feeding raw resumes directly to commercial LLMs (like GPT-4) causes stochastic, non-reproducible scoring, phantom skill fabrication, and high API latency.

  • Scores fluctuate wildly between identical prompts
  • No verifiable mathematical audit trail for hiring decisions
  • High API cost and token truncation on long resumes

✨ Our Solution

Strict Separation of Concerns: Deterministic models compute exact 6-signal math; LLMs only narrate verified JSON evidence.

Problem 3: The Career Direction Void

No Actionable Roadmaps

Existing tools only classify a candidate or search jobs. They never diagnose why a candidate fell short or how to systematically transition to their target role.

  • Rejections provide zero feedback on missing competencies
  • Candidates don't know which projects to build for high ROI
  • Generic advice is not tailored to the candidate's actual resume

✨ Our Solution

Dense Semantic RAG + 28 Career Taxonomy Tracks: Diagnoses exact skill gaps and provides 3-phase milestone roadmaps with portfolio project blueprints.

Runtime Trace

Trace of a Single Request: From Drag & Drop to Results Render

1. User Uploads Resume (`app/upload/page.tsx`)

User drops a PDF (e.g., Bassem_Ramadan_Resume.pdf). Frontend validates file extension and size (<5MB), then dispatches a multipart POST to POST /api/upload.

2. Next.js API Routes to FastAPI (`app/api/upload/route.ts`)

Calls RemoteResumeProvider.extractProfile() which forwards the file buffer to FastAPI POST /api/extract on port 8000.

3. Entity Extraction & Normalization

FastAPI runs PyMuPDF layout analysis → splits into regex sections → feeds text blocks into GLiNER v2.1 NER → normalizes detected skills against lib/resume/ontology.py → classifies domain with DeBERTa sequence classifier.

4. Deterministic Career Fit Engine (`POST /api/career-map`)

Candidate profile is evaluated across all 28 career tracks. Calculates exact skill ratios, project keyword overlaps, prototype centroid cosines, and applies the Anti-Hallucination Gate.

5. Groq Evidence Explanation (`POST /api/careers`)

The resulting similarity data is sent to Groq's 120B model to generate conversational justifications and highlight missing competencies.

6. Interactive UI Render (`app/profile/page.tsx` & `app/careers/page.tsx`)

Renders the Candidate Profile Card, Verified Skills chips, Top-5 Career Recommendation meters, KNN peer benchmarks, and opens the floating AI Career Advisor chatbot.

The Mathematical Core

The 6-Signal Deterministic Career Fit Engine

Why did we build a mathematical formula instead of letting an LLM guess? Because mathematics cannot hallucinate, provides 100% reproducible results, and guarantees full legal transparency.

Fit Score = 0.35·S + 0.20·P + 0.20·M̃ + 0.10·Edu + 0.10·Exp + 0.05·C
35% Skill Match (S)
20% Project Relevance (P)
20% Semantic Prototype (M̃)
10% Education Match (Edu)
10% Experience Match (Exp)
5% Domain Classifier (C)
Detailed Signal Definitions

How Each Signal is Computed

  • Skill Match (35%): Ratio of verified extracted candidate skills that match the taxonomy's required skills: |matched_skills| / |required_skills|
  • Project Relevance (20%): Overlap between candidate project descriptions and domain project keywords: |matched_keywords| / |required_keywords|
  • Semantic Similarity (20%): Cosine similarity between candidate dense embedding and the target domain's L2-normalized centroid: cos_sim(cand_vec, proto_vec)
  • Education Match (10%): Binary check (1.0 or 0.0) verifying if candidate degree matches field keywords (e.g., "Computer Science").
  • Experience Match (10%): Binary check verifying if historical job titles match domain roles (e.g., "Developer", "Software Engineer").
  • Classification Signal (5%): DeBERTa model confidence if the primary predicted category matches the domain.
Anti-Hallucination Gate

Preventing Semantic Vocabulary Drift

A common failure of pure vector embeddings is that generic corporate words ("management", "systems", "analysis") can cause an Accountant's resume to have moderate cosine similarity to IT prototypes.

🛡️ The Relevance Gate Formula:

If a candidate has 0 matched skills AND 0 matched projects for a target career track, the semantic component is penalized by 80%:

# Anti-Hallucination Relevance Gate
effective_semantic = semantic_score

    effective_semantic = semantic_score * 0.20

LLM Orchestration, Prompt Engineering & Dense RAG

How we engineered prompts and retrieval pipelines to ensure the Groq 120B model provides grounded career advisory without ever fabricating credentials.

Multi-LLM Fallback Strategy

Zero-Downtime Resilience

The system executes a sequential fallback across top-tier open-source LLMs hosted on Groq's high-speed LPU infrastructure:

  1. Primary: openai/gpt-oss-120b (Flagship reasoning & roadmap synthesis)
  2. Secondary: allam-2-7b (Fast sovereign model fallback)
  3. Tertiary: qwen/qwen3.6-27b (Multilingual & technical backup)
  4. Offline Fallback: Deterministic rule-based template engine in chatbot.py
Dense Semantic RAG

Domain Roadmap Retrieval

lib/career/rag.py indexes expert career milestones, high-ROI certifications, and portfolio project blueprints from data/career_roadmaps_kb.json.

  • Chunks indexed into 5 categories per role (Overview, Tech Stack, Projects, Certs, 3-Phase Roadmap)
  • Encoded via SentenceTransformer into normalized dense vectors
  • Retrieves top-3 relevant chunks using dot product cosine similarity + 0.35 target career boost
Prompt Engineering Rules

5 Strict Guardrails

Our system prompt (prompts/chatbot.txt) enforces 5 critical boundaries on the LLM:

  • English Only: Guarantees technical term consistency
  • Grounding Constraint: Never claim a skill that is not present in Extracted Skills
  • Structured Markdown: Responses must include checklists, roadmap phases, and portfolio blueprints
  • Think-Tag Sanitization: Regex filters strip internal reasoning tags (<think>) before UI render
